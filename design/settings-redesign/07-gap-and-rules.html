Reglas compartidas · el juego que Uso y Acerca de estrenan, y que los demás paneles pueden adoptar

Cuatro reglas, cero tokens nuevos: secciones separadas por una hairline, aire y velo al final de todo pane que scrollee, columnas fijas para lo tabular y sub-etiquetas calladas

Esto no es un rediseño de nada: es el juego de reglas que las hojas 05-usage.html y 06-about.html usan, escrito para que el cableado sea mecánico y para que el próximo panel —la sonda de entorno y los paquetes de la 0.9.0, que se van a construir dentro de este marco (S5)— no tenga que inventar su propia separación. Cada regla nace de una pieza que la app ya tiene: .provider + .provider y .urow + .urow ya son runs con hairline (T3 se las dejó a Cuenta y a Actualizaciones), y el aire y el velo son las dos declaraciones que faltan.

Lo que cuesta. Una regla general obliga a revisar los paneles que ya existen: hoy ningún pane de Ajustes tiene aire ni velo abajo, incluidos los dos que sí scrollean (Cuenta y Actualizaciones), así que este par de declaraciones cambia también su borde inferior aunque el pedido fuera Uso. Es a propósito —lo de «el botón está pegado» le pasa a todo pane largo— y se dice aquí para que no sorprenda en la revisión.

R1

Una sección es un run separado por una hairline, no una caja

Un grupo de ajustes que no es una sola cosa no lleva tarjeta: lleva su nombre, su aire y una 1px var(--border) que lo separa del anterior. La tarjeta se reserva para la unidad real (una previsualización de tema, una fila que se elige).

La medida del aire: 18 arriba y 18 abajo de cada sección, y 14 de aire más el subtítulo dentro. Es el ritmo del diálogo, no uno nuevo: 18 es el gap entre el riel y el pane y el aire entre mensajes.

Precedente en el código: .settings-pane .provider + .provider y .settings-pane .urow + .urow (apps/desktop/src/app.css). Estreno: .uprov + .uprov (Uso) y .agroup (Acerca de).

/* el run: sin caja, sin radio, sin gap */
.uprov { width: 100%; padding: 18px 0; }
.uprov:first-child { padding-top: 2px; }
.uprov + .uprov {
  border-top: 1px solid var(--border);
}
/* Acerca de usa el mismo gesto por grupo */
.agroup {
  margin-top: 16px;
  padding-top: 14px;
  border-top: 1px solid var(--border);
}

R2

Todo pane que scrollee termina en 24 de aire y un velo de 24

Dos declaraciones en .settings-pane, y el número es el mismo en las dos a propósito: cuando el scroll llega al final, el velo cae sobre relleno y no desvanece contenido. Nunca el último bloque contra la fila de «Cerrar».

Por qué el velo es una máscara: una mask-image lee solo el alfa del gradiente, así que sirve cualquier token opaco —--text lo es en los seis temas— y ningún hex entra en la hoja.

Coste medido: en WebView2 la barra de scroll se pinta dentro del elemento, así que el pulgar también se desvanece en los últimos 24px. Alternativa si molesta: un ::after con position:sticky;bottom:0 y background:linear-gradient(to bottom,transparent,var(--surface)), a cambio de un elemento más. Y el prefijo: escribir también -webkit-mask-image con el mismo gradiente, porque las WebView2 anteriores a Chromium 120 solo entienden la forma con prefijo.

.settings-pane {
  /* el aire: era 4px 0 0 4px */
  padding: 4px 0 24px 4px;
  /* el velo, con el mismo 24 */
  mask-image: linear-gradient(
    to bottom,
    var(--text) calc(100% - 24px),
    transparent 100%);
  /* y la forma con prefijo, por WebView2 viejo */
  -webkit-mask-image: linear-gradient(
    to bottom,
    var(--text) calc(100% - 24px),
    transparent 100%);
}

R3

Lo tabular va en columnas fijas, declaradas una vez y compartidas

Si dos hermanos dibujan las mismas columnas, la plantilla se declara una sola vez, en la propiedad --ucols del contenedor, y cada fila la usa. Así el «reinicia en 17d» y el «reinicia en 4h» empiezan en la misma x, y no hay forma de desalinearlos sin tocar la plantilla.

La trampa que evita: alinear a la derecha con margin-left:auto dentro de un flex hace que el texto más ancho empiece más a la izquierda —es exactamente lo que el mantenedor vio en «billing»—. Una columna con text-align:left no tiene ese problema.

Dónde más sirve: la sonda de entorno de la 0.9.0 (pieza · versión · estado · acción) y los paquetes son la misma forma. Acerca de ya usa la versión corta de la regla: grid-template-columns: 132px minmax(0,1fr).

.usecs {
  --ucols: 96px minmax(0, 1fr) 46px 112px;
}
.uwindow {
  display: grid;
  grid-template-columns: var(--ucols);
  align-items: center;
  gap: 0 12px;
}
.upercent { text-align: right; }
.ureset   { text-align: left; }

R4

Una sub-etiqueta es 11px, 600, mayúsculas y --faint

La etiqueta de sección de la casa, aplicada un nivel más abajo: agrupa las ventanas de un límite («claude», «command code», «credits», «Gemini Models») sin dibujar una caja ni competir con el nombre del proveedor.

El dato no se toca: text-transform es pintura, no contenido — un lector de pantalla sigue leyendo «Gemini Models», y el valor sigue siendo el del paquete (D7).

Ya está en design/system.md: «Section labels are 11–12px uppercase with letter-spacing: .05em–.08em in --faint». La regla solo dice cuál de las dos tallas y que esta es la de un sub-nivel.

.ulimit-head {
  display: flex;
  align-items: baseline;
  gap: 8px;
  margin: 0 0 4px;
  color: var(--faint);
  font-size: 11px;
  font-weight: 600;
  letter-spacing: .05em;
  text-transform: uppercase;
}
/* un límite alcanzado: la palabra Y el color */
.ulimit.reached .ulimit-head {
  color: var(--warning);
}

Los otros paneles cortos, contra las cuatro reglas

La pregunta era si Idioma, Notificaciones y Home del shell ya cumplen, sin rediseñarlos. La respuesta corta: los tres cumplen R1 y R4 (no tienen tarjeta que sobrar ni sub-etiquetas que dibujar), R2 les es indiferente porque no scrollean, y R3 no les aplica porque no dibujan filas tabulares. Ninguno necesita una línea de CSS; el que sí la necesita es Cuenta, que scrollea y hoy termina a hueso. El detalle, panel por panel, en la tabla.

Apariencia cumple — y R1 dice por qué las seis previsualizaciones sí pueden ser cajas: cada una es una unidad le falta — scrollea (seis filas de 64 + aire en 480) y termina a hueso: hereda R2 no aplica cumple — la etiqueta «Tema» ya es de esa familia

Dos observaciones que no son de estas reglas y no se tocan aquí: Home del shell usa el control viejo .home-choice (12px, pressed en --tint) donde Idioma y Notificaciones usan .seg; y Apariencia es el único panel que scrollea con contenido que no es una lista, así que R2 le cambia el borde inferior con más razón que a nadie.

Lo que esta hoja no estrena

Ni una cadena —por eso no hay columna en inglés—: las cuatro reglas son CSS y ninguna escribe palabras. Ni un token: los cinco valores que se usan (--border, --faint, --warning, --text, --surface) ya están en design/system.md. Ni un movimiento: el velo es estático y prefers-reduced-motion sigue apagando los 120ms del riel, los botones y los enlaces. Ni una hex: el gradiente del velo usa un token y el diagrama del corte usa var(--surface).

Lo único que hay que anotar en design/system.md cuando se cablee: --ucols es una propiedad de componente (como --swatch y --dot) que el código pone por elemento y no un token de tema; y el pane de Ajustes estrena el par padding-bottom + mask-image, que conviene que quede escrito en la sección del panel de Ajustes de ese archivo.
